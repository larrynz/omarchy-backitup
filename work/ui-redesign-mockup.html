UI / UX Redesign · Mockup v1

BackIt Up

A restic backup widget for the Omarchy bar. Today it is a narrow column of same-weight monospace rows: the interface works, but it makes you read every line to find the one that matters. This redesign keeps the popup small and the monospace soul, and changes what your eye lands on first.

Rendered with the live Akane palette (colors.toml) and JetBrainsMono Nerd Font, using the shell's real spacing and type scale. The panel is 360 px (440 px for browsers), exactly the constraint the real widget lives in.

01

The idea

Five rules govern every screen below. They are the answer to "it works but it's flat" — flat is a hierarchy problem, not a colour problem.

1 · Answer one question first

  • Every open starts with a single plain-language verdict: Protected, Backing up, Backup failed, Never backed up. The current panel opens on the word "Backups" — a noun, not a status.

2 · Stop overloading red

  • Running currently uses the theme accent (#e15a48) and failure uses urgent (#d6453d). On Akane those are two reds. The redesign gives each state its own hue: green healthy, cyan working, amber warning, red failed, grey never-run.

3 · Shape carries meaning

  • Status is a coloured dot, a pill, or a badge — not just tinted text, so it survives a colourblind eye and a bar full of coloured glyphs.

4 · Progressive disclosure inside 360 px

  • The first screen shows the health summary, a compact per-destination line, and three actions. Audit verdicts, snapshot detail and retention move one tap deeper instead of stacking as dim caption text.

5 · One header grammar

  • Overview, Restore, Manage and Setup all share the same header: back arrow, title, context control on the right. Today each view invents its own.

What changed

  • Hero verdict. "Backups" becomes "Protected" with a shield and the age of the newest copy as the second line. Glanceable in under a second.
  • Status is a shape. Dot → coloured, pill → word. The audit and snapshot verdicts collapse from two dim lines into two check tags that only shout when they are not green.
  • Metrics get a rhythm. Size, snapshot count and last delta sit in a single wrapped line with the numbers in the foreground colour — not one grey sentence.
  • Actions are weighted. One filled primary ("Back Up Now"), two equal secondaries ("Restore", "Manage"), and configuration demoted to a quiet footer.
  • Schedule is visible. "daily at 03:00" answers "is this thing even on?" without opening the config.
Proposed data. The schedule line and "next run" read from the destination's existing schedule; showing the computed next fire time would need one extra field from status --json. Low effort, high reassurance.

The aggregate view scales

  • One verdict for the set. "1 of 3 needs attention" is the only sentence you read when something is wrong; the failing destination is named right underneath it.
  • Cards, not a paragraph. Each destination keeps its own dot and pill, so health is scanned vertically instead of parsed line by line.
  • The primary action adapts. "Back Up Now" becomes "Back Up All" when there is more than one destination — the current panel already knows this, the label just never says it.
  • No forced expansion. A healthy destination stays one line; the failing one carries its reason in the hero, not in six lines of caption.

A run is a story, not a number

  • Ring, not a hairline. The 3 px bar becomes a ring at the top left, where the shield was — the same real estate, now legible from across the desk.
  • Phases replace the vague phrase. Unlock → Scan → Copy → Prune, with the current step lit. This is where the run actually is, and it never lies.
  • Colour is cyan, not red. "Working" stops looking like "failed".
  • Stop is the only red thing. It sits alone, full-width and destructive, so it cannot be hit by accident.
  • Other destinations are visible. With several configured, a queued one says so instead of disappearing.
Proposed data. Throughput, ETA and the phase step map cleanly onto the existing progress.phase and byte counters; rate and ETA would be computed shell-side from two polls. The phase list is the only genuinely new information and progress.phase already carries it.

Lead with the recovery, not the alarm

  • Name the reason. The current panel says "A backup failed" and hides the cause in the log. The reason belongs in the hero.
  • Answer "how bad?". The most important number after a failure is the age of your last good copy. It gets its own card with an age pill.
  • A way out. "Try again" is the primary, "View log" is one tap away.
  • The bar badge matches. Same red, same triangle — a shape you can see in the corner of your eye.

The empty state sells the feature

  • Explain the value, once. The dedup/encrypt/retention promise belongs here, where a new user is deciding, not buried in a README.
  • One button. No menu to explore. "Set up backups" enters the wizard.
  • Set an expectation. "Takes about a minute" removes the last reason to put it off.

History you can see

  • Timeline chips. Four visible snapshots with date and size, newest selected. Today the date is hidden inside a dropdown — you cannot see how far back your history goes or how big each point is.
  • Breadcrumb. The path is a line you can read and click, not a single grey /home/alex fragment.
  • Filter. The listing already handles typing (it blocks the vim key catcher while browsing, so this was always intended); the redesign surfaces the field.
  • Multi-select. Tick files and a sticky footer says exactly what will be restored and where. The current flow restores one row per click.
  • Restore never overwrites. The footer names the dated folder (~/Restored/…) so the safety property is visible, not implied.
  • Folders navigate, files queue. Chevron for folders, tick/plus for files — two shapes, two jobs.
Proposed data. Per-snapshot sizes need one field in the snapshots payload (summary.total_bytes_processed or a repo lookup). Everything else — paths, entries, sizes, file counts — already arrives from snapshots and ls.

The whole history, one row each

  • Every snapshot is visible. The dropdown becomes a list; finding the one to prune no longer means opening a menu.
  • Delete lives on the row. Quiet until hover, tinted red on approach — it cannot be mistaken for the primary action.
  • The confirm names the stakes. Date, destination, file count, and the word "cannot be undone".
  • Retention is explained. The footer line tells you why four snapshots is normal, not a problem.
  • Busy work stays honest. A delete with prune can take minutes; the list stays visible behind a "Pruning…" line with the modal dismissed.

One decision per screen

  • Stepper. Five dots with the current label. You always know how much is left, which is the single biggest fix for a long form.
  • Folders are objects. Each source is a chip you can remove; the add action is a dashed button. Today these are rows with a bare "×".
  • Suggestions lower the blank-page cost. Naming common folders turns a path-typing exercise into a click.
  • Back / Continue, not Apply / Cancel. Verb pairs tell you where you are going.

Show the result before it happens

  • A real review step. The current form applies from wherever you happen to be; the review lets you catch a wrong path before a repository is created.
  • Retention becomes a picture. Four numbers in a row explain the policy far better than a config key — and reassure that space is bounded.
  • Schedule is a control, not a label. A segmented picker with the chosen time beside it; the raw systemd OnCalendar string moves under an "advanced" disclosure.
  • Password mode is stated. "(command)" is visible at review, so nobody is surprised where the secret lives.
  • Edit reuses the wizard. Opening edit-config jumps to Review with every step marked done — same screens, no second form to maintain.

Build plan

Phased so each stage ships on its own and nothing is blocked on the proposed data fields.

Phase 1 — Overview (highest value, no new data)

  • Add semantic status colours to Panel.qml; stop using accent for "running".
  • Build the hero, destination card and grouped-action components.
  • Collapse audit and snapshot verdicts into check tags.

Phase 2 — Restore & Manage

  • Snapshot timeline chips + breadcrumb + filter + multi-select restore queue.
  • Manage list with per-row delete and the named confirm.

Phase 3 — Setup wizard

  • Five steps with a stepper; reuse for edit-config by jumping to Review.
  • Retention visual and schedule segmented control.

Phase 4 — Bar & polish

  • Distinct bar glyph per state, dot badge, verdict-first tooltip.
  • Optional compact label behind a setting.

New QML components to add

  • StatusHero.qml — verdict, colour, badge, optional ring.
  • DestinationCard.qml — dot, name, pill, metrics, health tags.
  • ActionButton.qml — primary / secondary / danger, icon + label.
  • SnapshotChip.qml, Breadcrumb.qml, Stepper.qml.

Status shape & edge cases to keep

  • The failed badge is a shape as well as a colour — keep it.
  • Config-invalid and units-not-installed states still need their own calm, explanatory screens; they slot in as extra hero variants, not error dumps.
  • A destructive action (stop, delete) is always alone and always red.
